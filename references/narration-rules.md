# 口语化旁白与去 AI 味准则 (Narration Rules)

在代码视频中，旁白是唯一的听觉线索。如果旁白带着浓厚的“AI 翻译腔”或“自媒体八股味”，整个视频的技术可信度会瞬间归零。

必须严格遵循以下口语化准则：

---

## 一、骨架防伪：结构对称是最大的 AI 味

很多人以为去 AI 味只是改词，实际上**骨架工整才是最致命的破绽**：

1. **拒绝并列小标题逐条等长展开**：
   - 错误范例：三个子标题分别写三段，每段恰好三句话，字数几乎一致；
   - 正确做法：挑一两个最致命的点讲透（可以讲两百字），剩下的点用一段话甚至一句话直接带过。
2. **段落长短悬殊**：
   - 允许关键判断一句话独立成段；
   - 允许细节描述展开成长段；
   - 节奏要有起伏，而不是像流水线压出的标准砖块。
3. **彻底砍掉自作聪明的元叙述**：
   - 绝对禁止说：“我把这些对比整理成了一张表格，看起来更直观”、“接下来让我们探讨第三个维度”；
   - 直接把画面切出来，嘴里直接讲内容。
4. **拒绝抹平棱角的假过渡**：
   - 不要为了顺滑而强行连接。段落之间允许硬切，像工程师在黑板前突然敲黑板：“但这里有个最要命的问题很多人没注意到”。
5. **拒绝抖机灵金句收尾**：
   - 不要每段最后都来一句“不是……而是……”或者谐音梗金句，全文至多留一两句自然总结，多一点都油腻。

---

## 二、用词铁律：把书面评论腔换成人话

| 严禁使用的书面评论腔 / 假大空词汇 | 替换口语化表达 / 处理方式 |
| :--- | :--- |
| **“分野 / 取舍 / 宿命 / 生态 / 赋能 / 演进”** | 直接说事：“到底是拆还是合”、“多花了几秒钟”、“代码改起来费劲” |
| **“不是 A，而是 B” 反复句式** | 换成直陈句：“以前我们老觉得是 A 的问题，其实根本不是，就是 B 搞的鬼。” |
| **“有分析发现 / 有人做过对比”** | 给出具体出处：“Anthropic 团队自己在评测里发现”、“有个实测数据很扎心” |
| **“这一步听着像废话，但其实至关重要……”** | 删掉铺垫，直接说要做什么、为什么。 |
| **通篇连绵不绝的破折号（——）** | 换成逗号、句号，或者直接另起一句。 |
| **空洞升华结尾（如“让我们共同期待智能时代的到来”）** | 删掉！停在务实的工程结论上：“别让代码去模拟你们公司的组织架构图，能用一个主循环搞定的，就别开子智能体。” |

---

## 三、真实活人的语气特征

1. **第一人称与同理心**：
   - 多用：“说实话，我一开始也觉得……”、“大家搭这个的时候肯定都踩过坑”、“其实仔细一想挺离谱的”。
2. **真实承认局限**：
   - 允许说：“这个在某些边缘场景下目前还没那么完美”、“Anthropic 自己也没把话说死，比如极端并发的时候就还得老老实实用子任务”。
3. **动作与现场感**：
   - 把抽象描述换成动作：“你看这行代码”、“光标在三个 Agent 之间来回跳”、“控制台的延迟计时器一路飚红”。
