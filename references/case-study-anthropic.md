# 经典实战范例：Anthropic 智能体折叠长文拆解 (Case Study)

本案基于 Anthropic 官方工程文章《Building agents: When to fold subagents into your main agent loop》的拆解全过程，作为“文章转代码视频”的标杆范例。

---

## 阶段一：材料解构输出

1. **核心痛点**：
   - 很多团队按照部门架构拆分智能体，导致“康威定律”直接写进代码；
   - 多智能体层层传递，就像传话游戏，上下文有损压缩，细节严重丢失；
   - 嵌套调用导致延迟爆炸（动辄 8 秒以上）。
2. **反直觉主张**：
   - 随着模型自身推理和 Thinking 能力提升，应该“减少子智能体，折叠回单一主循环”；
   - 配合渐进式披露（Progressive Disclosure），按需动态检索工具与技能，既不撑爆上下文，又保留原汁原味的信息。
3. **关键数据与踩坑**：
   - 折叠后实测端到端运行速度提升 2 倍（耗时缩短近 50%）；
   - Claude Code 通过动态加载技能与工具，将高级模型 System Prompt 砍掉了 80% 以上；
   - 踩坑警告：折叠为工具后，模型可能绕过验证直接下结论，必须靠端到端 Evals 保障。

---

## 阶段二：非对称视频大纲（3分半节奏）

* **开场（0:00 - 0:35）**：
  * **画面**：`<ArchitectureGraph />` 模拟多部门臃肿 Agent 调用拓扑，延迟计数器狂飙。
  * **旁白**：直击痛点，指出大家搭 Agent 经常把公司组织架构图写成了代码。
* **第一幕（0:35 - 1:20）**：
  * **画面**：`<TelephoneGameLoss />` 演示传话游戏丢失关键细节，`<ConsoleLatencyTracker />` 演示等待子 Agent 时的耗时折磨。
  * **旁白**：点出多智能体最致命的两大病灶——信息有损衰减与延迟翻倍。
* **第二幕（1:20 - 2:05）**：
  * **画面**：`<CodeDiffViewer />` 动态展示复杂编排器代码折叠成简洁的 `while (agent.running)` 主循环，绿标打出 `2x Faster`。
  * **旁白**：解释为什么现在可以折叠——新模型自己的推理与反思已经能管好任务流。
* **第三幕（2:05 - 2:55）**：
  * **画面**：`<ProgressiveDisclosureVisualizer />` 演示 Claude Code 的极简 Prompt，以及需要时通过 `ToolSearch` 动态挂载技能的全过程。
  * **旁白**：讲清单循环如何解决工具过多上下文膨胀的问题，说明业务团队未来应该沉淀 Skills 而不是搞独立的 Agent。
* **第四幕（2:55 - 3:25）**：
  * **画面**：`<DecisionMatrix />` 弹窗警报真实翻车案例，切出红绿双卡片明确何时保留、何时折叠。
  * **旁白**：客观指出折叠的危险点与评测红线，指出什么时候坚决不能折叠（并发与极限上下文）。
* **尾声（3:25 - 3:45）**：
  * **画面**：代码窗口定格在极简主循环上，光标自然闪烁。
  * **旁白**：一句工程师工程准则利落收尾：“能用单循环搞定的，就别开子智能体。”

## 阶段三：活人旁白切片节选

> “不知道从什么时候开始，大家搭 Agent 第一反应就是把系统拆碎。每个业务团队认领一个子智能体，写自己的 Prompt，挂自己的工具。表面上模块化、好分工，实际上一跑起来卡得要死。
>
> Anthropic 这篇文章其实挺扎心的，它直接点破了一件事：很多人的多智能体架构，本质上就是把康威定律写进了代码里——你在模拟你们公司的部门墙，而不是在做最优的系统设计。
>
> 两个 Agent 之间互相汇报，其实就是传话游戏。主模型拿到的是二手甚至三手总结，原始诉求里那些微妙的细节全被磨平了。外面看着是一个简单的提问，底下三个 Agent 在那里客套地来回调用，用户在前端已经等得想关网页了……”
